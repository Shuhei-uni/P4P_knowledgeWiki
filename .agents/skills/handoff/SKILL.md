# Handoff

Write a paste-ready brief that lets a new chat understand why the work was done,
what happened, and what the results now show. Leave the new direction for the
user to add in the next chat.

Use the current conversation first. Read only specific records needed to verify
a material result or recover missing context. Select details that change how the
next chat should understand or use the work.

Build a short, connected account:

- Set title Handoff
- **Why the work was done:** Briefly explain what the user had wanted to achieve
  and why the work and approach were chosen. Use past tense and treat this as
  background to the work, rather than instructions for the next chat. Label
  inferred reasons.
- **Work and results:** What was actually done, what the latest evidence shows,
  and what that means for the goal. Keep completed work, attempted work, and
  proposals distinct. Carry uncertainty that could change the interpretation.
- **What changed:** The finding, failure, constraint, or user decision that
  explains the present position. Include a discarded approach only if its
  reason could prevent repeating an unhelpful path.

Use plain language and a few short paragraphs. Keep essential numbers and
constraints; link to the few key artifacts with a phrase explaining each one's
use. Leave logs, file inventories, and setup details in their owning records
unless the next task needs them. State material gaps instead of guessing.

Return the brief directly to the user in chat. Do not create or edit files,
create a new chat, or transfer the brief through tools. Preparing a handoff ends
with the text output; execute the next task only when the user requests it.
