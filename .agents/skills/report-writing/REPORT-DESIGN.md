# Report design

Use HTML as a rendering medium, but design the result like a professional technical report rather than a website, dashboard, or slide deck.

The goal is a calm, clean report with strong hierarchy, readable figures, restrained colour, and enough whitespace for the important evidence to breathe.

## Visual direction

Prefer:

- editorial, report-like layouts;
- generous whitespace;
- strong typography and clear section hierarchy;
- a predictable content column and grid;
- large, legible figures;
- visually quiet tables;
- consistent alignment and spacing;
- neutral backgrounds;
- colour only when it communicates information.

Use size, weight, spacing, and position as the main hierarchy tools. Keep the visual language restrained.

## Density

Prefer removing information to shrinking information.

Important content should remain comfortable to read at normal viewing size. Secondary material should be concise and integrated into captions or prose. If something only fits by becoming tiny, reconsider whether it belongs in the report.

Keep the number of text levels small. Captions may be smaller than body text, but they should still read comfortably without zooming.

## Layout

Let whitespace separate ideas before reaching for boxes, cards, borders, or filled backgrounds.

Give important figures substantial space. Keep related text close to the figure it explains, but do not compress plots simply to fit more material beside them.

Use HTML and CSS for precise layout and typography while preserving the visual character of a serious report.

## Colour

Default to a neutral palette. Introduce colour when it carries meaning: distinguishing comparison series, identifying a threshold or failure, highlighting the result under discussion, or encoding another real analytical distinction.

Keep decorative colour subordinate to the evidence. A report should still make sense when viewed largely in monochrome.

## Figures

Treat figures as first-class report elements.

Make each plot large enough to understand without zooming. Keep axes, labels, units, legends, and annotations clear at normal reading size. Reduce visual noise and keep figure styling consistent across the report.

Use emphasis selectively so the important comparison or pattern is apparent without making every element compete for attention.

When several plots answer one analytical question together, compose them as a coherent multi-panel figure rather than as unrelated dashboard cards.

## Tables

Keep tables quiet and readable. Prefer spacing, alignment, typography, and restrained rules over heavy fills or borders.

Highlight only values that genuinely deserve attention. Keep units and comparison bases obvious.

## HTML character

The report may use HTML freely for layout, responsive sizing, navigation, and useful interaction, but the visual result should remain document-like.

Choose report conventions over application UI conventions. Use a strong reading flow instead of a collection of widgets.

## Rendered review

Inspect the rendered report, not only the HTML source.

Review the whole page first:

- Is the hierarchy obvious?
- Does the report feel calm and coherent?
- Is colour doing useful work?
- Is any text uncomfortably small?
- Do important figures have enough space?
- Does whitespace feel intentional?
- Can anything be removed without losing meaning?

Then inspect each figure and table at normal viewing size for legibility, alignment, visual noise, and consistency.

Revise the rendered result until the presentation feels like a professional technical report rather than a generated webpage.
