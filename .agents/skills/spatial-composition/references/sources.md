# Sources and limits

Public material reviewed on **9 October 2026**. These are primary documentation,
author-published teaching, and first-person practice accounts, not a ranking of
skill popularity. Links to mutable repositories should be rechecked before future
imports. The skill is an original synthesis; no external skill or book is bundled.
Source attribution does not grant rights to copy artwork, code, fonts, or full text.

## Website-oriented agent guidance

### S1

[Anthropic: frontend-design skill](https://raw.githubusercontent.com/anthropics/skills/main/skills/frontend-design/SKILL.md).
The published guidance connects visual choices to the subject, a distinctive focal
element, and critique during construction. Its restraint principle informs this
skill's selective emphasis. Transfer the reasoning, not a mandatory typeface,
colour scheme, or ban on common patterns. No benchmark of superiority is implied.

### S2

[OpenAI: Frontend prompt instructions](https://developers.openai.com/api/docs/guides/frontend-prompt).
The guidance differentiates operational interfaces from marketing compositions,
preserves existing conventions, and calls for inspection of the implementation.
Use it to adapt composition to the task and verify the rendered result, rather
than turning every artifact into a landing page. Model-specific details can change.

### S4

[Paul Bakaus: Impeccable](https://github.com/pbakaus/impeccable).
The project documents targeted refinement, visual critique, technical auditing,
and live browser iteration. This skill borrows the distinction between those
activities, not an assertion that a detector can measure taste. Impeccable is an
independent project, not a frontier-lab design standard.

### S13

[Google Labs Code: Stitch design-md skill](https://raw.githubusercontent.com/google-labs-code/stitch-skills/main/plugins/stitch-utilities/skills/design-md/SKILL.md).
The skill records atmosphere, colour roles, geometry, layout and depth in a
semantic design definition. This motivates preserving reasons alongside values.
Our layer/attention/reading table extends that approach; it is not Google's schema
or a requirement to use Stitch. No external MCP is needed to use this skill.

## Frontier-lab creative practice

### S3

[OpenAI: How Codex became a collaborator for OpenAI's creative team](https://openai.com/index/codex-collaborator-creative-team/).
This first-party account describes Chad Nelson using project context and custom
controls to explore composition and lighting. It motivates optional editable
controls and human selection, not a claim that the model has acquired human-like
spatial understanding. It is a practice account, not a controlled evaluation.

### S14

[Lenny Rachitsky: interview with Jenny Wen, 1 March 2026](https://www.lennysnewsletter.com/p/the-design-process-is-dead).
The public episode page identifies design practice at Anthropic and lists changing
processes, tool use, taste, and judgement as topics. The complete written discussion
was not available in the retrieved public page. This is further listening only:
no detailed workflow rule here relies on inaccessible interview content.

## Conventional teaching for designers

### S5

[Steve Schoger and Adam Wathan: Refactoring UI](https://www.refactoringui.com/).
The public table of contents covers hierarchy, de-emphasis, overlap, depth, and
spacing. These topics inform the reference structure. The paid book was not
consulted or reproduced; the examples and repair instructions here are original.

### S6

[Google: Material Design, Elevation and shadows](https://m1.material.io/material-design/elevation-shadows.html).
This archived design-system documentation explains relationships between surfaces,
elevation and shadows. Use it as a spatial model, not a current universal UI
specification. Its platform-specific distances and component styles are not poster
rules, and its shadow language need not govern an editorial composition.

### S7

[Getty: Understanding Formal Analysis, Elements of Art](https://www.getty.edu/education/teachers/building_lessons/formal_analysis.html).
The educational reference explains space, positive/negative space, form, colour,
line and texture. It supplies vocabulary for observing composition; it does not
prescribe our particular separator layout.

### S8

[Nielsen Norman Group: Visual Hierarchy in UX, Definition](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/).
This describes hierarchy using relationships such as scale and contrast. It
supports inspecting relative prominence. The skill's three-order model and
observation-first review are our synthesis, not a validated NN/G testing protocol.

### S9

[Aurora Harley / Nielsen Norman Group: Proximity Principle in Visual Design](https://www.nngroup.com/articles/gestalt-proximity/).
The article explains perceived grouping through proximity and how relationships
can change in responsive layouts. Use it to examine clusters and spacing instead
of enclosing everything in an identical container.

### S10

[Erik Kennedy: 7 Rules for Creating Gorgeous UI, Part 1](https://www.learnui.design/blog/7-rules-for-creating-gorgeous-ui-part-1.html).
Kennedy teaches attention to light, space, and grayscale structure. This skill
uses grayscale as an optional diagnostic, not as a requirement to suppress colour
in expressive or quantitative scientific imagery.

## Implementation checks

### S11

[MDN: Stacking context](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Positioned_layout/Stacking_context).
Use this documentation when debugging actual CSS parent/child stacking. Perceived
depth and paint order are different problems; changing a z-index alone may solve
neither. Verify API/browser details against the current implementation.

### S12

[W3C: Understanding WCAG 2.2, Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
Use for digital text contrast requirements and their exceptions. This is a
legibility constraint, not an aesthetic score, a full accessibility audit, or proof
that a printed poster will be readable on its intended stock.

## What this skill adds

The three separate orders, explicit overlap/clear-space relationships, semantic
layer table, controlled composition variants, observation-first readback, and
small-repair loop are proposed agent instructions derived from the research and
user brief. They are not claimed as a published unified theory. Their usefulness
must be judged on rendered artifacts and human feedback; use the
[evaluation scenarios](../evals/scenarios.md) to test revisions.
